# STM32 手柄 USB 不识别问题排查报告

**工程**: `D:\stm32\project\手柄`
**芯片**: STM32F103C8T6
**日期**: 2026-09-05

---

## 一、问题现象

手柄插上电脑后，电脑**完全识别不到**设备（设备管理器无变化 / 无"未知设备" / 无提示音）。

---

## 二、代码层面全面检查结果

经过对整个工程的详细审查，**代码逻辑层面未发现会导致 USB 完全无法枚举的致命 bug**。以下是各模块的检查结论：

### 2.1 系统时钟配置 ✅

- 系统时钟: HSE * 9 = 72MHz（`SYSCLK_FREQ_72MHz` 已定义）
- USB 时钟: PLLCLK / 1.5 = 48MHz（`Set_USBClock()` 中 `RCC_USBCLKSource_PLLCLK_1Div5`）
- 时钟配置符合 USB 2.0 全速设备要求

> ⚠️ **潜在风险**: 如果外部晶振（HSE）损坏或未焊接，PLL 将无法启动，系统回退到 HSI（8MHz），此时 USB 时钟不正确，导致无法枚举。
> 
> **排查方法**: 用示波器测 PA8（MCO 复用功能）输出，或在代码中通过串口打印 RCC 时钟状态寄存器确认 HSE 是否就绪。

### 2.2 USB 初始化流程 ✅

初始化顺序（`main.c`）:
```
Set_System()              → 使能 PWR 时钟
USB_Interrupts_Config()   → 配置 NVIC 中断
Set_USBClock()            → 配置 USB 时钟 48MHz
USB_Init()                → 调用 Joystick_init()
  └─ PowerOn()            → USB 强制复位 + 设置中断掩码
  └─ USB_SIL_Init()       → 完整中断掩码使能
```

顺序正确，符合 ST 官方例程规范。

### 2.3 USB 中断配置 ✅

- 低优先级中断: `USB_LP_CAN1_RX0_IRQn`，抢占优先级 1
- 唤醒中断: `USBWakeUp_IRQn`，抢占优先级 1
- 中断向量已正确链接到 `usb_it.c` 中的处理函数（map 文件验证）
- `IMR_MSK` 包含所有必要中断（CTR / RESET / SUSP / WKUP / SOF 等）

### 2.4 端点配置 ✅

| 端点 | 类型 | 方向 | 最大包长 | 缓冲区地址 |
|------|------|------|----------|------------|
| EP0 | 控制 | 双向 | 64B | RX=0x18, TX=0x58 |
| EP1 | 中断 | IN | 8B | TX=0x100 |

- BTABLE 起始地址: 0x00
- 缓冲区地址无重叠，空间充足

### 2.5 描述符检查 ✅

**设备描述符**（18 字节）:
- VID = 0x0483（ST）
- PID = 0x5750
- bcdUSB = 2.00
- bMaxPacketSize0 = 64
- bNumConfigurations = 1

**配置描述符**（34 字节）:
- 1 个接口（HID 类）
- 1 个端点（EP1 IN 中断）
- wTotalLength = 34 ✓

**HID 报告描述符**（80 字节）:
- 15 按钮 + 1bit padding
- Hat Switch（4bit）+ 4bit padding
- 5 个 8bit 轴（X / Y / Z / Rx / Ry）
- 声明长度与实际字节数一致 ✓

**字符串描述符**:
- 语言 ID: 0x0409（英语-美国）
- 厂商: "STM32"
- 产品: "STM32 GamePad"
- 序列号: 从芯片唯一 ID 动态生成

### 2.6 GPIO 引脚冲突检查 ✅

| 引脚 | 功能 | 配置来源 |
|------|------|----------|
| PA0~PA5 | ADC 模拟输入 | adc.c |
| PA6~PA7 | 按键上拉输入（R3/L3） | joystick.c |
| PA8 | WS2812 推挽输出低 | main.c |
| PA9 | USART1 TX 复用推挽 | usart.c |
| PA10 | USART1 RX 浮空输入 | usart.c |
| **PA11** | **USB_DM** | **USB 硬件自动管理** |
| **PA12** | **USB_DP** | **USB 硬件自动管理** |
| PA13~PA14 | SWD 调试 | 默认 |

**PA11/PA12 未被任何代码手动配置**，上电默认为浮空输入，USB 外设使能后自动接管。**无引脚冲突**。

### 2.7 其他外设干扰检查 ✅

- USART1 中断优先级（0）高于 USB（1），但仅接收中断，无数据时不触发
- 软件 I2C（PB12/PB13）不使用硬件外设，纯 GPIO 模拟，无中断
- SysTick 用于延时，未开启中断
- 无 DMA / TIM 等可能频繁触发中断的外设

## 三、最可能的原因（按概率排序）

### 🔴 原因 1：USB D+ 上拉电阻问题（概率最高）

**现象**: 电脑完全无反应，设备管理器无任何变化。

代码中假设：
```c
/* PA12(USB_DP) 已通过板载 1.5k 电阻上拉, 无需软件控制 */
void USB_Cable_Config (FunctionalState NewState)
{
  /* 空实现 */
}
```

**如果实际硬件上 D+ 没有 1.5k 上拉电阻（或上拉到错误的电压），主机根本检测不到设备的存在**，就像没插一样。

**排查方法**:
1. 用万用表测 PA12（USB_DP）引脚电压，正常应为 3.3V 左右
2. 检查 D+ 和 3.3V 之间是否有 1.5kΩ 电阻
3. 如果板子上有"USB 软连接"GPIO（比如某些板子用 PC13 控制 D+ 上拉），需要在代码中配置该 GPIO

**如果确认是硬件上拉缺失**，有两种修复方案：

**方案 A（硬件）**: 在 D+ 和 3.3V 之间焊一个 1.5kΩ 电阻。

**方案 B（软件）**: 如果板子上有专用 GPIO 控制 D+ 上拉，修改 `USB_Cable_Config()` 函数来控制该 GPIO。

---

### 🟠 原因 2：USB 线或接口问题

**排查方法**:
1. 换一根确认好的 USB 数据线（注意：有些充电线只有电源线没有数据线）
2. 换一个 USB 口（台式机试试后面板的口）
3. 检查 USB 座子是否虚焊、D+/D- 是否接反
4. 用万用表测 USB 座子 D+/D- 到 PA12/PA11 是否导通

---

### 🟠 原因 3：HSE 晶振不起振

**现象**: 程序可能运行（OLED 亮、串口有输出），但 USB 不工作。

如果 HSE（外部高速晶振）损坏或未焊接，`SetSysClockTo72()` 会启动失败，系统继续使用 HSI（8MHz 内部 RC 振荡器）。此时 PLL 未启动，USB 时钟不正确。

**排查方法**:
1. 看 OLED 是否正常显示、串口是否有输出 —— 如果都正常，说明程序在运行
2. 用示波器测晶振引脚（PD0/PD1）是否有 8MHz 波形
3. 或在代码中加入 HSE 启动失败检测，用串口打印状态

**快速验证**: 可以临时改为 HSI 倍频到 48MHz 方案（不推荐，精度不够，但能验证是不是晶振问题）。

---

### 🟡 原因 4：供电问题

**排查方法**:
1. 测板子 3.3V 电压是否稳定
2. USB 口供电能力是否足够（某些笔记本 USB 口电流有限）
3. 尝试用带供电的 USB Hub

---

### 🟡 原因 5：PA11/PA12 引脚被意外配置

虽然目前代码中没有配置 PA11/PA12，但如果后续修改中不小心配置了这两个引脚，可能导致 USB 无法工作。

**确认方法**: 在 `USB_Init()` 之前加入以下代码，强制将 PA11/PA12 设为模拟输入：
```c
GPIO_InitTypeDef gpio;
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
gpio.GPIO_Pin  = GPIO_Pin_11 | GPIO_Pin_12;
gpio.GPIO_Mode = GPIO_Mode_AIN;
GPIO_Init(GPIOA, &gpio);
```

## 四、逐步排查建议（按顺序）

### 第一步：确认程序是否在运行
- OLED 是否显示开机动画和菜单？
- 串口（115200）是否能收到 "STM32F103 GamePad Ready!"？

  ✅ 如果都正常 → 程序在跑，问题在 USB 相关
  
  ❌ 如果都不工作 → 可能是晶振/供电/烧录问题

### 第二步：检查硬件连接
- 换 USB 线、换 USB 口再试
- 万用表测 D+（PA12）电压，应在 3.0~3.6V 之间（上拉正常）
- 测 D-（PA11）电压，应接近 0V（无数据时）

### 第三步：检查 D+ 上拉电阻
- 如果 D+ 电压为 0V 或很低 → 上拉电阻缺失或损坏
- 这是最常见的原因

### 第四步：检查晶振
- 如果程序运行但 USB 不枚举，且 D+ 有 3.3V
- 用示波器测 8MHz 晶振是否起振
- 或在代码中添加 HSE 启动状态检测

### 第五步：添加调试输出
在 `usb_it.c` 的 `USB_LP_CAN1_RX0_IRQHandler` 中加一个全局计数变量，看 USB 中断是否触发：
```c
volatile uint32_t usb_irq_count = 0;
void USB_LP_CAN1_RX0_IRQHandler(void)
{
  usb_irq_count++;
  USB_Istr();
}
```
然后在主循环中通过串口或 OLED 显示这个计数。
- 如果计数为 0 → 中断没触发，可能是硬件问题或时钟问题
- 如果计数在增加 → 说明有 USB 通信，问题在枚举阶段

## 五、代码层面可优化的点

虽然不是导致"完全识别不到"的原因，但以下几点可以改进：

### 5.1 字符串描述符索引越界风险

`usb_prop.c` 中 `Joystick_GetStringDescriptor()`:
```c
if (wValue0 > 4)   // 允许 0~4，但数组只有 4 个元素（0~3）
```
建议改为 `if (wValue0 >= 4)`。

### 5.2 增加 HSE 启动失败检测

当前 `SetSysClockTo72()` 如果 HSE 启动失败会静默返回，系统继续用 HSI（8MHz），USB 必然失败。建议添加失败指示，比如闪烁 LED 或串口打印错误。

### 5.3 显式配置 USB 引脚为模拟输入

虽然 USB 硬件会自动接管引脚，但显式配置 PA11/PA12 为模拟输入更安全，可以避免任何 GPIO 数字电路对 USB 信号的干扰。

---

## 六、总结

**代码本身没有致命 bug**，USB 描述符、端点配置、中断处理、初始化流程均符合 ST 官方规范。

**最可能的原因依次是**：
1. 🔴 **D+（PA12）没有 1.5k 上拉电阻** —— 最常见
2. 🟠 USB 线坏了或只是充电线
3. 🟠 8MHz 晶振不起振
4. 🟡 USB 座子虚焊或 D+/D- 接反

**建议优先排查 D+ 上拉电压**，这是最快能确认的硬件问题。
