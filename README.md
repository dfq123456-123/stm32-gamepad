# STM32F103C8T6 双模游戏手柄

基于 STM32F103C8T6 的自制游戏手柄固件。双摇杆 + 双扳机 + 15 键，支持 **USB HID 有线** 和 **蓝牙串口** 两种上报方式，带 OLED 菜单、参数掉电保存，以及一套针对摇杆串扰的采样处理方案。

- MCU：STM32F103C8T6（72 MHz，标准外设库）
- 屏幕：128×64 SSD1306 OLED（软件 I2C）
- 编译：Keil uVision 5

---

## 功能特性

**输入采集**

- 6 路 12 位 ADC：左摇杆 XY、右摇杆 XY、左扳机 LT、右扳机 RT
- 15 个按键 + 十字键，按键接 GND 用内部上拉，省掉 15 颗外部电阻
- 自适应量程：不写死 ±2048，按每轴实测极值动态归一化
- 自适应滤波：小幅移动重滤波去抖，大幅移动轻滤波保跟手
- 开机自动校准中心，支持运行中重新校准

**抗串扰（三层叠加）**

相邻 ADC 通道会因为采样电容残留电荷互相"拖动"，表现为动左摇杆时右摇杆跟着动。本项目用三层手段解决：

1. **dummy 冲刷**：切换通道后丢弃第一次转换，冲掉采样保持电容的残留电荷
2. **8× 过采样取均值**：每通道采样 8 次求平均，从源头磨掉尖峰
3. **交错采样顺序**（`{0,2,4,1,3,5}`）：PA0~PA5 在 LQFP48 上是物理连续的 6 个脚，按交错顺序采样可以把相邻通道在时间上隔开

**两种上报模式**

| 模式 | 通道 | 用途 |
|---|---|---|
| 游戏控制器模式 | USB HID，9 字节报告 | 接 PC / Steam，免驱识别为游戏手柄 |
| 蓝牙控制器模式 | USART1 透传，16 字节帧 | 接蓝牙模块控制小车、机械臂等下位机 |

**其他**

- OLED 中文菜单：死区 / 滤波 / 亮度 / 熄屏 / 校准 / 蓝牙参数
- 所有参数写入片内 Flash，掉电不丢
- 空闲自动熄屏，唤醒时强制重绘（避免增量刷新留下残影）

## 硬件连接

| 功能 | 引脚 | 说明 |
|---|---|---|
| 左摇杆 VRX | PA0 | ADC1_IN0 |
| 左摇杆 VRY | PA1 | ADC1_IN1 |
| 右摇杆 VRX | PA2 | ADC1_IN2 |
| 右摇杆 VRY | PA3 | ADC1_IN3 |
| 左扳机 LT | PA4 | ADC1_IN4 |
| 右扳机 RT | PA5 | ADC1_IN5 |
| 十字键 上/下/左/右 | PB11 / PB1 / PB10 / PB0 | 内部上拉，按下为低 |
| 按键 A / B / X / Y | PB8 / PB7 / PB9 / PB6 | |
| LB / RB | PB15 / PB14 | |
| L3 / R3 | PA7 / PA6 | 摇杆下压 |
| HOME / MENU / VIEW | PB3 / PB4 / PB5 | 返回 / 菜单 / 切换模式 |
| OLED SCL / SDA | PB12 / PB13 | 软件 I2C |
| USART1 TX / RX | PA9 / PA10 | 接 HC-05/06 蓝牙模块 |
| USB D- / D+ | PA11 / PA12 | |

> 按键统一接 GND、MCU 内部上拉，读取到低电平即为按下。PB3 / PB4 默认是 JTAG 脚，代码里已做 `GPIO_Remap_SWJ_JTAGDisable` 重映射。

## 编译与烧录

**编译**：用 Keil uVision 5 打开 `demo.uvprojx`，点 Rebuild。也可以用命令行全量重建：

```bat
"C:\Keil_v5\UV4\UV4.exe" -r demo.uvprojx -o build_log.txt
```

> 增量编译（`-b`）有时会沿用旧的 `.o`，产物体积对不上。要核对产物大小或出交付版本时，用 `-r` 全量重建。

**烧录**：Keil 里点 Download（ST-Link / J-Link）。USB 接 PA11/PA12，烧完插电脑应能直接枚举成游戏控制器。

编译结果参考：`Code=18972 RO-data=4032 RW-data=544 ZI-data=7880`，0 Error 0 Warning。

## 已知限制

- 摇杆轴映射为逻辑交叉（`AXIS_CH_LX = L_VRY`），因为摇杆模块是 90° 错位安装的；如果换用正常朝向的模块，需要把 `joystick.h` 里的轴映射改回直连。
- 右摇杆 Y 轴在 HID 里做了反向（`buf[7] = 0x80 - v`），是硬件物理方向决定的，不要删。
- 修改 USB 报告描述符后，PC 需要重新枚举，Steam 等平台的按键绑定可能要重设。
